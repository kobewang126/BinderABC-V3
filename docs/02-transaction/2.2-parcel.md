# 2.2 从普通数据到 Parcel

## 2.2.1 两个整数之后

第 2.1 章的 `mini_binder_payload` 固定包含两个整数。要传一个字符串，或者同时传多个不同类型的数据，就需要规定它们在字节缓冲区中的排列方式，以及接收者如何知道每个字段在哪里结束。直接传递 C 指针不行：指针是发送进程的虚拟地址，接收进程不能据此访问发送者的内存。

本章先在用户态实现一个小型 Parcel：把一个无符号 32 位整数和一段字符串编码到缓冲区，再按相同顺序读取。本章**尚未将 Parcel 接入 RPC**。完整源码位于 `examples/2.2/`；第 2.1 章的驱动保存在对应章节目录中。

## 2.2.2 先观察字节布局

约定整数占 4 字节，使用小端顺序；字符串由 4 字节长度、原始字节和补齐字节组成。长度不包括补齐字节，也不包含字符串结束符。写入整数 42 和六字节字符串 `Binder` 后：

```text
偏移      内容                         字节（十六进制）
0..3      整数 42                      2a 00 00 00
4..7      字符串长度 6                 06 00 00 00
8..13     字符串 Binder                42 69 6e 64 65 72
14..15    补齐到 4 字节边界            00 00
```

总长度是 16 字节。4 字节对齐让后续字段从 4 的倍数偏移开始；不同协议可以选择不同对齐规则。这里的字符串是指定长度的字节序列，不要求以 `\0` 结尾，也不验证字符编码。

## 2.2.3 缓冲区与读写位置

源码：`examples/2.2/include/parcel.h`，第 8–13 行。

```c
struct parcel {
    unsigned char *data;
    size_t capacity;
    size_t size;
    size_t position;
};
```

`data` 指向调用者提供的缓冲区，`capacity` 是容量，`size` 是已写入长度，`position` 是读取位置。初始化后两者为 0；写入追加到 `size`，`parcel_rewind()` 只把读取位置重置到开头，不清除内容。读写顺序由双方约定，这个例子不包含类型标签。

源码：`examples/2.2/userspace/parcel_demo.c`，第 14–20 行。

```c
    parcel_init(&p, buffer, sizeof(buffer));
    if (parcel_write_u32(&p, 42) || parcel_write_string(&p, "Binder", 6))
        return 1;
    printf("encoded size: %zu bytes\n", p.size);
    parcel_rewind(&p);
    if (parcel_read_u32(&p, &number) || parcel_read_string(&p, &text, &length))
        return 1;
```

写入与读取顺序一致，才能依次还原整数和字符串。下面看这两个操作的关键实现。

## 2.2.4 编码与解码整数

源码：`examples/2.2/userspace/parcel.c`，第 16–36 行。

```c
int parcel_write_u32(struct parcel *p, uint32_t value)
{
    if (p->size > p->capacity || p->capacity - p->size < 4)
        return -1;
    for (unsigned int i = 0; i < 4; ++i)
        p->data[p->size + i] = (unsigned char)(value >> (i * 8));
    p->size += 4;
    return 0;
}

int parcel_read_u32(struct parcel *p, uint32_t *value)
{
    uint32_t result = 0;
    /* ... 检查待读取数据是否完整 ... */
    for (unsigned int i = 0; i < 4; ++i)
        result |= (uint32_t)p->data[p->position + i] << (i * 8);
    p->position += 4;
    *value = result;
    return 0;
}
```

先检查剩余空间，再移动位置；失败时位置不变。逐字节操作确定了小端格式，也避免将可能未对齐的字节地址强制转成 `uint32_t *`。用减法检查剩余空间之前先确认位置有效，避免无符号数下溢。

## 2.2.5 编码字符串

源码：`examples/2.2/userspace/parcel.c`，第 38–55 行。

```c
int parcel_write_string(struct parcel *p, const char *text, size_t length)
{
    size_t padding = (4 - length % 4) % 4;
    /* ... 检查长度和剩余容量 ... */
    parcel_write_u32(p, (uint32_t)length);
    if (length)
        memcpy(p->data + p->size, text, length);
    p->size += length;
    memset(p->data + p->size, 0, padding);
    p->size += padding;
    return 0;
}
```

先检查长度能否用 32 位表示，再检查长度前缀、内容和补齐是否都能放下；这样失败时不会留下只写了一半的字段。`padding` 在 0 到 3 之间。调用者必须保证非空字符串的输入指针可读，且不与写入缓冲区重叠。

## 2.2.6 解码与不可信输入

源码：`examples/2.2/userspace/parcel.c`，第 57–74 行。

```c
int parcel_read_string(struct parcel *p, const unsigned char **text, size_t *length)
{
    size_t start = p->position;
    size_t padding;
    uint32_t n;

    if (parcel_read_u32(p, &n))
        return -1;
    padding = (4 - n % 4) % 4;
    if (n > p->size - p->position || padding > p->size - p->position - n) {
        p->position = start;
        return -1;
    }
    *text = p->data + p->position;
    *length = n;
    p->position += n + padding;
    return 0;
}
```

长度来自缓冲区，不能直接相信。代码先检查内容和补齐字节是否完整；如果长度字段本身完整而后续内容截断，则把读取位置恢复到字段开始。成功返回的 `text` 指向原缓冲区，不是新分配的字符串，也没有保证末尾有 `\0`；缓冲区必须在使用期间保持有效。

这个小接口假设 `struct parcel` 本身由可信代码正确初始化，返回指针参数有效，并且读取时底层数据不被并发修改；接入跨进程通信时还需要明确这些所有权和并发条件。

## 2.2.7 实验

在 Linux 环境中进入源码目录：

```sh
cd examples/2.2
make
./build/parcel_demo
./build/parcel_test
```

用户态实验不需要加载内核模块。实际输出：

```text
encoded size: 16 bytes
decoded: number=42, text=Binder
parcel tests passed
```

测试覆盖字节序、字符串补齐、容量不足、截断数据、空字符串和恶意长度；检查失败后读写位置没有被错误推进。本章目录只包含 Parcel 编解码、演示和测试；驱动实验请使用 `examples/2.1/`。

## 2.2.8 与 Android Binder 的距离

这里的 Parcel 是固定容量、调用者管理的用户态教学缓冲区，不兼容 Android Parcel，也没有接入驱动。Android 的 Parcel 除普通数据外还处理 Binder 对象和文件描述符等；它们不能作为普通整数或进程私有指针原样交给另一个进程。

对象偏移表用于告诉驱动事务数据中哪些位置包含需要特殊处理的对象。驱动需要检查偏移、大小和对象类型，并进行相应转换；本章没有实现偏移表、对象描述符或这些转换，将在后续对象章节讨论。

下一章将设计事务描述，把不同长度的载荷与请求、回复联系起来。
