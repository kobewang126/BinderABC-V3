# 3.3 在 Parcel 中描述对象

## 3.3.1 普通字节和对象有什么不同？

第 3.2 章通过实验用 Node 编号选择对象，但这个编号需要人工告知客户端。以后我们希望把对象本身放进事务，交给另一个进程。驱动必须知道 Parcel 的哪些位置是普通整数，哪些位置包含需要转换的对象；否则无法区分一个数值和一个对象标识。

本章先在用户态增加对象描述和位置表，观察数据布局并验证边界。**位置表尚未传给驱动，`LOCAL` 和 `HANDLE` 只是描述类型，不会创建 Node 或 Ref。** 跨进程转换留到下一章。

源码位于 `examples/3.3/`，驱动协议版本显示为 `0303`；本章新实验 `object_parcel_test` 只运行在用户态，沿用的 Node 示例仍可在配套驱动上运行。

## 3.3.2 对象位置表

```text
Parcel 字节区
  0..3    普通整数 42
  4..15   本地对象描述：type + value 的低 32 位 + 高 32 位
 16..19   普通整数 7
 20..31   引用描述：type + value 的低 32 位 + 高 32 位

对象位置表： [4, 20]
                 │   └── 指向第二个对象描述
                 └────── 指向第一个对象描述
```

位置是字节区内的偏移，既不是 2.7 章中的用户虚拟地址，也不是旧 Binder 的 `user_buffer_offset`。每个描述占 12 字节，按四字节对齐；对象值以两个 32 位整数编码，不依赖 C 结构体的填充布局。这里的 `value` 是演示数值，不应直接在其他进程中解引用。

源码：`examples/3.3/include/object_parcel.h`，第 9–22 行。

```c
#define OBJECT_PARCEL_MAX_OBJECTS 8U
#define OBJECT_PARCEL_LOCAL 1U
#define OBJECT_PARCEL_HANDLE 2U

struct object_parcel {
    struct parcel bytes;
    uint32_t offsets[OBJECT_PARCEL_MAX_OBJECTS];
    size_t count;
};

struct parcel_object {
    uint32_t type;
    uint64_t value;
};
```

`bytes` 仍使用第 2.2 章的 Parcel，`offsets` 和 `count` 标识其中的对象描述；`parcel_object` 是解码后的用户态结果，不是直接复制到 Parcel 的内存布局。位置表在本章与字节区分开保存，还没有成为驱动协议的一部分。

## 3.3.3 写入对象

源码：`examples/3.3/userspace/object_parcel.c`，第 12–25 行。

```c
int object_parcel_write(struct object_parcel *p, uint32_t type, uint64_t value)
{
    size_t start = p->bytes.size;
    if ((type != OBJECT_PARCEL_LOCAL && type != OBJECT_PARCEL_HANDLE) ||
        p->count >= OBJECT_PARCEL_MAX_OBJECTS || start > UINT32_MAX || start % 4)
        return -EINVAL;
    if (parcel_write_u32(&p->bytes, type) || parcel_write_u32(&p->bytes, (uint32_t)value) ||
        parcel_write_u32(&p->bytes, (uint32_t)(value >> 32))) {
        p->bytes.size = start;
        return -ENOSPC;
    }
    p->offsets[p->count++] = (uint32_t)start;
    return 0;
}
```

先保存写入前位置，检查类型、容量、偏移能否放入 32 位及对齐。三个字段全部写入后才追加位置；空间不足时把有效数据长度恢复到写入前。失败时底层缓冲区中可能留下无效字节，但它们不属于 `size` 范围，也没有对应位置项。

## 3.3.4 读取和边界检查

源码：`examples/3.3/userspace/object_parcel.c`，第 27–45 行。

```c
int object_parcel_read(const struct object_parcel *p, size_t index, struct parcel_object *object)
{
    struct parcel reader = p->bytes;
    uint32_t type, low, high;
    size_t offset;
    if (!object || p->count > OBJECT_PARCEL_MAX_OBJECTS || index >= p->count ||
        reader.size > reader.capacity) return -EINVAL;
    offset = p->offsets[index];
    if (offset % 4 || offset > reader.size || reader.size - offset < 12 ||
        (index && (p->offsets[index - 1] > offset || offset - p->offsets[index - 1] < 12)))
        return -EINVAL;
    reader.position = offset;
    if (parcel_read_u32(&reader, &type) || parcel_read_u32(&reader, &low) ||
        parcel_read_u32(&reader, &high) ||
        (type != OBJECT_PARCEL_LOCAL && type != OBJECT_PARCEL_HANDLE)) return -EINVAL;
    object->type = type;
    object->value = (uint64_t)low | ((uint64_t)high << 32);
    return 0;
}
```

函数检查当前对象及其前一项的顺序和重叠，并检查当前对象的对齐、剩余长度和类型；读取副本不会改变原 Parcel 的读取位置。调用方若要验证完整位置表，应逐项检查；这段用户态代码不能代替未来驱动对不可信输入的检查。

## 3.3.5 构建与实验

这次实验只需 C 编译器，不需要加载驱动：

```sh
cd examples/3.3
make build/object_parcel_test
./build/object_parcel_test
```

在 Ubuntu 24.04 ARM64、Linux 6.8.0-147 上实际输出：

```text
object offsets, decoding, malformed data and rollback passed
```

测试混合普通整数和两个对象，检查位置与解码值，再测试重叠、越界、非法类型和缓冲区空间不足。完整章节的驱动、Node 和并发回归也已在同一环境编译并运行。

## 3.3.6 限制和下一步

本章没有把位置表交给驱动；两个类型只是教学编码，不能与 Android 的 `flat_binder_object` 互通。下一章将讨论对象描述如何跨进程转换，以及为什么接收方需要自己的 Ref 和 handle。
