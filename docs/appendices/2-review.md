# 第二篇自测

## 题目

1. 2.1 中哪些请求数据由服务端映射读取？为什么这仍不是完全零拷贝？
2. Parcel 如何编码字符串，双方为什么必须约定读取顺序？
3. 2.3 的事务 `size` 在发出请求和收到回复时分别表示什么？
4. 2.4 为什么要求客户端释放映射回复？服务端请求页是否用相同方式释放？
5. 2.5 的 `code` 与 2.6 的 BC、BR 命令分别解决什么问题？
6. 2.7 中 `data_address`、内部槽位位置和对象位置表有什么不同？
7. 两笔事务倒序回复时如何匹配客户端？请求槽和回复槽何时复用？

## 参考答案

1. 服务端从映射读取请求参数；客户端到驱动的复制、内核写映射区及元数据和回复复制仍然存在。
2. 示例使用长度、字符串字节和对齐填充；读写双方按约定格式和顺序解释字节，才能正确找到下一字段。
3. 提交时是请求载荷长度；成功返回后是实际回复长度。
4. 驱动无法知道客户端何时读完回复，因此通过显式释放允许回复页复用。服务端提交回复后不再使用请求页，没有对应的单独释放命令。
5. `code` 选择服务操作；BC、BR 描述用户与驱动之间的命令和返回事件。本例 READ、WRITE 的协议与 Android 不同。
6. `data_address` 是接收进程的用户地址；槽位位置是驱动在映射内定位数据的内部偏移；对象位置表标识 Parcel 内需要转换的对象。
7. 驱动按事务 ID 查找对应槽。正常情况下客户端取走回复后请求槽可复用，读取映射回复并发送 `BC_FREE_REPLY` 后回复槽可复用。
