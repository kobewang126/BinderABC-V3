# 第三篇自测

## 题目

1. 用户态对象、对象上的操作和服务端函数指针各起什么作用？
2. 3.2 的 Node 保存什么？驱动会执行 Node 保存的用户态 cookie 吗？
3. Parcel 里为什么需要对象类型和对象位置表？
4. 本地对象交给另一进程时，驱动如何从 Node 得到接收方 handle？
5. 两个进程中的 handle 都是 1，是否一定指向同一个 Node？
6. 多服务端场景中，驱动怎样找到负责处理目标对象的服务端？
7. 已有 handle 转交给另一个进程时，为什么不能直接复制 handle 数字？

## 参考答案

1. 对象选择接收请求的服务对象，操作码选择对象的操作，服务端在自己的用户态通过函数指针执行具体函数。
2. 示例 Node 保存编号、所属服务端和 cookie；驱动转交 cookie，不在内核执行用户态指针。
3. 类型和位置表帮助驱动区分普通字节与需要转换的对象描述，避免将普通整数当作对象处理。
4. 驱动根据本地对象描述查找所属 Node，再为接收方建立或复用指向该 Node 的 Ref，并返回该 Ref 对应的 handle。
5. 不一定；handle 的含义属于各自的打开文件上下文。
6. 先通过调用方 handle 找 Ref，再找到 Node 及其拥有者，最后把请求交给所属服务端。
7. handle 是发送方上下文中的编号；驱动须找到其 Node，并在接收方建立或复用对应 Ref。
