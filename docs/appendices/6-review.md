# 第六篇自测

## 题目

1. fd 数字和内核中的打开文件有什么区别？`dup()` 后的两个 fd 为什么共享读位置？
2. 为什么把 fd 数字作为普通整数交给另一个进程不能完成文件传递？
3. 发送 fd 对象时，驱动在哪个进程上下文调用 `fget()`？接收方的 fd 在哪个上下文安装？
4. 发送方关闭原 fd 后，驱动持有的文件为什么仍可交付？
5. 两个目标 fd 中第二个预留失败时，驱动如何处理已经预留的第一个编号和文件引用？
6. 请求 fd 成功交付后，发送方取消调用，谁负责关闭接收方的 fd？
7. 回复 fd 的读取发生 `EFAULT` 或 `EMFILE` 后，本例为什么可以重试？已经安装的 fd 随回复释放自动关闭吗？

## 参考答案

1. fd 是进程 fd 表中的编号；多个 fd 可引用同一打开文件，因而共享该打开文件的位置等状态。
2. 接收方的相同数字在自己的 fd 表中查找，可能是其他文件或无效编号；需要传递文件引用并安装新 fd。
3. 发送线程上下文的 fd 表中取得文件引用；接收线程上下文中预留和安装新 fd。
4. `fget()` 取得独立引用，发送方 `close()` 只释放其原 fd 持有的引用。
5. 驱动撤销已预留编号，未成功交付的文件引用由驱动释放；请求失败的具体错误见 6.3。
6. 接收方；已经安装到接收方 fd 表的描述符由接收方关闭。
7. 本例回滚预留编号但保留尚未交付的文件引用，供当前线程修复后重试；已经安装的 fd 必须由接收方自行关闭。
