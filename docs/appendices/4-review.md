# 第四篇自测

## 题目

1. 本例的 `mini_binder_proc` 与一次 `open()`、`dup()` 分别是什么关系？
2. 本例通过什么入口找到管理者？它是否是 Android 的完整上下文管理者 Node？
3. 管理者保存的 handle 为什么要经过转换才能交给客户端？
4. 为什么同一个 proc 要记录多个 Binder 线程？4.3 是否已经实现线程级待办？
5. proc todo 和等待队列各保存什么？两个服务线程怎样避免领取同一工作？
6. 请求尚未领取时取消，与已经领取后取消，处理方式有什么不同？
7. 一个 Ref 传回 Node 拥有者时，为什么可以恢复本地对象描述？

## 参考答案

1. 独立 `open()` 创建独立 proc；`dup()` 共享同一个打开文件及其 proc。
2. 本例目标 handle 和 Node 均为 0 时选择已注册的管理者入口；它直接保存文件，不是完整的上下文管理者 Node。
3. 管理者的 handle 属于其 proc；驱动根据对应 Node 为客户端建立或复用自己的 Ref 和 handle。
4. 多个线程可能使用同一文件，驱动需要区分它们；4.3 只记录身份，没有线程级 todo。
5. todo 保存待处理事务，等待队列负责休眠唤醒；线程在状态锁保护下取出工作并改变状态。
6. 未领取时可从 todo 删除并回收；已领取时保留取消状态，等待旧回复或服务端退出后回收。
7. 驱动发现接收方就是 Node 的 owner，返回先前登记的本地 cookie；用户态负责校验并找到自己的对象。
