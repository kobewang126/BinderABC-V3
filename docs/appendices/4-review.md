# 第四篇自测

## 题目

1. 一次独立 open、一次 dup 与 mini_binder_proc 分别是什么关系？
2. Node 的 owner 与 Ref 所属 proc 为什么可以不同？
3. 把已有 handle 传回对象拥有者时，为什么返回 LOCAL cookie 而不是新 Ref？
4. 4.3 创建 Node 后，是否立刻具备接收调用的全部条件？
5. 同一个上下文怎样区分本次读取请求还是回复？双向调用是否意味着支持同步嵌套回调？
6. 客户端怎样从服务名称得到自己的 handle？为什么不能直接使用管理者保存的数字？
7. 管理者退出后，客户端已经取得的服务引用是否必然失效？
8. 第四篇结束时，是否已经有线程表、proc.todo 和线程专属回复？

## 参考答案

1. 每次独立 open 创建独立 proc；dup 共享打开文件及其 proc。
2. Node 归对象拥有者，Ref 归引用持有者；不同上下文通过各自的 Ref 指向同一个 Node。
3. 驱动发现接收方就是 Node 的 owner，恢复先前登记的 cookie；用户态负责找到本地对象。
4. 不具备，还需保持有效映射，并有执行读取和回复的用户态代码。
5. 用 MINI_READ_REQUEST / MINI_READ_REPLY 指定读取意图；本篇的双向调用先后完成，没有等待中的同步重入。
6. 用 handle 0 查询管理者，驱动将管理者 Ref 转换为客户端 Ref；handle 数字只在各自 proc 中有效。
7. 不必然，已有 Ref 指向服务 Node，不依赖管理者继续运行；服务拥有者退出则会使引用失效。
8. 都没有。此时请求仍扫描两个固定事务槽，调用与回复状态按打开文件保存；第五篇再逐步增加线程机制。
