# 第一篇自测

## 题目

1. 1.1 的客户端如何跨进程得到加法结果？直接传函数指针为什么不够？
2. 字符设备的 `open()`、`ioctl()` 和 `release()` 在示例中分别起什么作用？
3. 第一次同步 RPC 中，客户端提交请求后怎样等待服务端回复？
4. 1.3 只有一个事务槽，为什么仍需要考虑客户端中断后的迟到回复？
5. 1.4 的 `call_lock` 和 `state_lock` 分别保护什么？等待服务端时为什么不能持有后者？
6. 1.4 的多个客户端等待意味着有多笔事务同时在途吗？请求编号有什么作用？

## 参考答案

1. 双管道传递固定请求和回复；函数指针是所属地址空间中的地址，不能让另一个进程直接调用。
2. `open()` 建立文件上下文，`ioctl()` 交换命令和数据，最后一个文件引用释放时 `release()` 清理上下文。
3. 驱动发布请求并在等待队列上睡眠；服务端领取并提交回复后唤醒客户端，客户端检查状态并取得结果。
4. 客户端可能在服务端领取请求后中断；如果立刻复用槽，旧回复可能污染新调用，因此必须保护取消状态。
5. `call_lock` 串行化对单个调用槽的使用，`state_lock` 保护事务状态与数据。等待时须释放状态锁，服务端才能更新状态并回复。
6. 不是，仍只有一笔在途；编号用于识别请求并拒绝不匹配的迟到回复。
